# 安全

写给两类人：**准备把它挂到能被别人访问的地方的**，和**想搞清楚这东西凭什么敢碰自己服务器的**。默认假设不是"这是本机小工具"，而是"有人在网络上试"。

## 信任边界

| 面 | 谁能碰到 | 怎么守 |
|---|---|---|
| QQ 入站 | 任何给机器人发消息的人 | 硬白名单（私聊）+ 群聊默认全关；不在名单里的消息**既不转发也不抑制**，闸门在裁决之前 |
| 面板 HTTP | 绑定地址决定一切 | 凭据 + 会话 + CSRF + 锁定，见下 |
| 插件市场 | 你主动点安装才有网络 | 目录可整块关掉；下载→落盘→加载每一步都能拒绝，且明确报为什么 |
| 装进来的插件代码 | **它拿到的是机器人全部权限** | 唯一真正的防线是"你只装你信任的作者"，astrmai 不做沙箱 |
| 出网到模型端点 | 谁的密钥谁付费 | 遥测默认掐断；密钥只在麦麦自己的配置文件里 |

## 凭据

**口令**：内存困难哈希，标准库 `hashlib.scrypt`，`N=2^15, r=8, p=1, dklen=32`，16 字节随机盐，本机实测单次约 294 ms。参数和盐一起落盘（将来调参还能验旧凭据），比较走 `hmac.compare_digest`。这台机上没装 bcrypt/argon2，scrypt 是标准库里唯一像样的选择 —— 不是"够用就行"的妥协，是真的没有第二个选项。

**机器 token**：走 `sha256 + 盐`，不是 scrypt。这不是放松：token 是 32+ 位随机串、由程序每次请求都带，用它做内存困难哈希会让每个请求烧掉 0.3 s（实测一轮 21 次轮询 = 6.88 s）。口令是人打的、一天登几次，才值得慢。

**明文零落地**：初始口令只在生成的那一次打到控制台。不进文件、不进日志、不进任何 API 响应、不进状态 JSON。测试里真的把整个状态目录扫一遍，断言每一次出现过的明文都搜不到 —— 光看代码"应该没写"不算。

**初始口令是公开写死的 `astrmai-init`**（懒人版：不用去控制台找一个随机串）。它必须配两条硬约束，两条都在代码里：

1. `must_change` 挂着 → 除登录/改密/登出外一律 403，**带 token 也一样拦**；
2. 这个口令**只接受本机登录**（来源在回环才认）。

第 2 条有个反代陷阱：挂了 nginx 之后 TCP 对端永远是 `127.0.0.1`，看对端等于把公开口令对全网开放。所以这一条和爆破计数一样按 `_source()` 判 —— 只有显式 `ASTRMAI_PANEL_TRUST_PROXY=1` 才认 `X-Forwarded-For`。

`_source()` 取的是 **最右一段**，不是最左一段：最左是客户端自带的，拿它当来源，攻击者每次尝试换一个假 IP 就领一个新计数器，爆破锁定等于没有；最右那一段是我们自己的 nginx 追加的（`$proxy_add_x_forwarded_for`），客户端写不进去。伪造 `X-Forwarded-For: 127.0.0.1` 会被追加成 `127.0.0.1, <真客户端>`，取最右就还是远程地址，初始口令那条"仅本机"的防线因此守得住。测试里有两条专门打这两个洞。

**改密**：≥12 位、不等于初始口令、不在弱口令表里、字符不能太单一，且必须验当前口令。改密或 `/mai panel reset` → 全部会话立即作废（实测旧 cookie 再请求回 401）。

**恢复口不走 HTTP**：重置口令的能力只在 QQ 的管理员命令里。挂到面板上等于让未登录的人自己重置。

## 会话与请求

- Cookie：`HttpOnly` + `SameSite=Strict` + 限定 `Path=/astrmai`，**只有真的跑在 TLS 上才加 `Secure`**（HTTP 下加 Secure 等于自己把自己锁外面）。空闲 30 分钟 / 绝对 8 小时双超时，表上限 64 条。
- 写操作（非 GET）额外要求 `Origin`/`Referer` 的主机与 `Host`（或 `ASTRMAI_PANEL_PUBLIC_HOST`）一致。**带了这两个头却解析不出主机（`null`、被裁剪）按跨站拒绝** —— 沙箱 iframe 和 `data:` 页面的 Origin 就是 `null`，放过等于开 CSRF。
- 爆破锁定：按来源计数、时长指数递增（60 s 起，上限 15 分钟），**只拦登录端点**。这条是被自己的测试逼出来的：早期版本把同源已登录会话一起拒了，共享出口（一个公司一个 NAT）下等于自我 DoS。来源表上限 256，防止有人拿伪造 XFF 撑内存。
- 非回环绑定必须有证书，否则**拒绝启动**，并把两条出路写进报错：配 `CERT/KEY`；或确实躲在已加密隧道后面就显式设 `INSECURE=1`（这时才放行，并大声警告）。不"警告后继续"。

## 响应里能出现什么

`scrub()` 是最后一道：任何密钥字段只报"是否已配置/长度"这类形状，值一律不外传。两个坑都踩过并写进断言：

- 用子串匹配字段名会吞掉自家布尔字段 —— 曾经把 `key_present` 变成 `<redacted>`，屏上每个"故意没绑密钥"的任务都显示"密钥已配置"。**脱敏过滤器自己也会制造谎言**，所以现在是按词匹配、且只脱敏字符串/字节/容器值。
- 测试把面板全部响应拼起来搜凭据明文（token、口令、`sk-` 形状），搜不到才算过。

面板能看见的内容有三类，给账号之前先想清楚：

1. **裁决流水 200 条** —— 每条消息前 60 字预览 + 判给了谁。在内存，不落盘，重启即清空。
2. **日志环 400 条** —— 同上，内存环形缓冲。
3. **完整对话历史** —— 「扩展 → AstrBot 功能面 → 对话历史」从 `data/data_v4.db` 现读，能看到整条会话的消息正文（每条截 600 字），分页浏览。**这一类不落盘但也不在内存环里，是磁盘上本来就有的历史**； astrmai 只给读，**没有做删除入口**（删除仍然只在 AstrBot 官方面板那条路）。

把面板交给别人看之前，按这三条想，而不是只按"60 字预览"想。

## 供应链

- **永不代你 pip**：需要装依赖的插件在调用加载器之前就被拒绝，理由会返回。你有密钥在这台机上，装一个陌生包的 setup.py 等于把密钥端出去。
- **许可证取证**：搜索时从官方目录/索引带 `license`（多数标 `unknown`，因为两家目录本身不带），安装时从包内 `LICENSE`/metadata/README 判定并写进插件目录的 `.astrmai-license.json`，`/mai 许可证` 与面板「许可证清单」列出全部。**判不出就明写 unknown，不猜** —— 不分发时它只是信息，要分发时它就是依据。
- **上游遥测默认掐**：麦麦硬编码往第三方站点发心跳，融合版默认关掉，只有显式 `ASTRMAI_TELEMETRY=on` 才放行。
- **市场可整块关**：`ASTRMAI_MARKET_NETWORK=0` 之后，AstrBot 那条（api.soulter.top / 合集 codeload）和麦麦那条（hyybuth.xyz:10059，与遥测 :10058 同主机）**一起**关，目录、下载、许可证探测一律拒绝，本地缓存也不能当后门。要不要出网是你能一眼决定的一件事。
- **卸载有边界**：只允许删市场目录的直接子目录，越界路径直接拒绝（有测试）。

## 挂到能被别人访问的地方之前

1. 登录进去，**改掉初始口令**（不改就什么都干不了）。
2. 决定形态：能接受就只绑回环，用 SSH 隧道自己看；要走域名就 nginx + `TRUST_PROXY=1` + `PUBLIC_HOST=<域名>`。
3. 别用 `INSECURE=1` 裸奔到公网 —— 那条是给已经在加密隧道后面的场景留的口子。
4. 想要脚本调 API：设 `ASTRMAI_PANEL_TOKEN`（≥24 位），别把口令写进脚本。
5. 跑一遍 `.venv/bin/python run_tests.py`，特别是面板认证与攻击面那两项。
6. `astrmai_state/credentials.json` 权限收到只有你能读（它是哈希，但别留便利）。
7. 记住：**面板看得见群里聊了什么**。给它账号之前先想清楚。

## 这套东西没有防住什么

- 单管理员，没有多用户、没有权限分级、没有二次验证。
- **出站 TLS 上限被全局钉在 1.2**（`astrmai/tls.py` 包了 `ssl.create_default_context` 与 `httpx.create_ssl_context`）。这是实测取舍：某个兼容端点在 Python 的 TLS 1.3 握手会静默挂住，而两个脑子共用一个进程 —— 代价是同进程内**所有**出站都拿不到 1.3。要放开就删这一处调用，别在两个地方各钉一次。
- **宿主会 `os.chdir` 到麦麦根目录**（`astrmai/host.py`）。麦麦自己按相对路径找配置与数据库，这是把它的运行时搬进本进程的代价；进程内 `os.getcwd()` 从此不可信，任何新代码都要用绝对路径。`sys.modules["src.runtime"]` 被塞了个禁用桩，就是防上游那条会再次 chdir/劫持信号的路。
- 插件代码不隔离：装上就等于给了它机器人的全部权限（含你的模型密钥那台机器）。
- 面板能看见**完整会话文本**（上面那三类内容），靠"口令 + 绑定地址 + TLS"守，不靠加密存储 —— 内容本身不加密落盘（内存那两类根本不落盘）。
- 「初始口令只允许本机登录」这条防线，前提是反向代理按文档用 `$proxy_add_x_forwarded_for` **追加**真实来源。把 XFF 改成复制头情的代理不在信任模型里：那样客户端可以自己写 `127.0.0.1`。
- 端到端取证用本地桩模型；真模型下的行为请自己先看几轮。
